Data sources & methodology

All data is Ethiopia-specific. No pan-African or global dataset stands in for a national one.
  • Climate (temperature, rainfall, humidity) — NASA POWER API, queried per Ethiopian region at the representative coordinates in data/ethiopia_regions_reference.csv. Free, no API key.
  • National malaria burden — WHO Global Health Observatory OData API, filtered to SpatialDim = ETH.
  • ENSO phase — NOAA PSL Niño 3.4 index (East African rainfall teleconnection).
  • Regional 2024 case/death share — WHO Disease Outbreak News, Ethiopia, 31 Oct 2024 (Oromia 44%, Amhara 18%, Southwest 12%, South Ethiopia 7% of national cases). Shares for the remaining regions are an estimated apportionment from published endemicity literature, not an official statistic.

The regional-monthly case series that feeds the risk score is an apportionment of the national WHO annual trend by these regional shares and Ethiopia's known kiremt/belg seasonality — not raw EPHI PHEM/HMIS microdata (which has no public API). Swap in real EPHI/PHEM or DHS figures in the notebook's Cell 6 for a validated, thesis-grade result.

Wiring this dashboard to GitHub

This file is static HTML/JS with no build step — it reads four JSON files from data/dashboard/ at runtime and falls back to the seed data below if they're missing (e.g. on first load, before the notebook has run). To keep it live:
repo/ ├─ Ethiopia_MEWS_Dashboard.html ← this file (set as index.html, or point Pages at it) ├─ Ethiopia_MEWS_Colab.ipynb ← run in Google Colab; Cell 12 writes the JSON below ├─ scripts/fetch_ethiopia_data.py ← headless version of the notebook, for CI ├─ data/dashboard/ │ ├─ national_trend.json │ ├─ regional_risk.json │ ├─ climate_latest.json │ └─ meta.json └─ .github/workflows/update-ews-data.yml ← runs fetch_ethiopia_data.py on a schedule, commits refreshed JSON, dashboard picks it up 1. Push this repo to GitHub, enable Pages (Settings → Pages → deploy from branch, root or /docs). 2. Either run the Colab notebook's Cell 13 to push data/dashboard/*.json manually, or enable the included GitHub Actions workflow to refresh it automatically (e.g. daily). 3. The dashboard has no server-side dependency — GitHub Pages alone is enough to serve it.
